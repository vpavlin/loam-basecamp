# Delivery: fork 0.1.4 → upstream v0.3.0 (analysis, 2026-10-02)

Source-read only; runtime items marked UNVERIFIED.

## Sources
- Module v0.3.0 = `bec8594`; pins logos-delivery `ca28145` (v0.39.0), builder 0.3.1, rln_module `25357cfd`, lez_rln `11b2f00b`.
- Our fork `vpavlin/logos-delivery-module@loam-0.1.4` = `7d93aeb` on `0fb3a74` (branched from upstream `c21ffb8`, 56 module commits behind).
- Library `8ad99f1..ca28145` = 161 commits. nim-segmentation `0593ef7c`.

## Decisions and blockers

1. **Channel wire break (main interop blocker).** v0.39.0 (`8bdccc32`) wraps every channel payload in a
   `SegmentMessage` protobuf, even single-segment; 0.38.1 passed it through. The marker is still
   `RELIABLE-CHANNEL-API/1`, so nodes can't tell. Channel API 0.38.1 ↔ 0.39 fails both ways (new decoder
   drops old frames silently; old peers see protobuf bytes). Everything else on the wire matches
   (protocols, WakuMessage, nim-sds `b12f5ee`, cluster 2, 8 shards, entry nodes); plain relay is compatible.
   loam_core reads the raw event and peels SDS itself (`delivery_bearer.hpp:89-95`), so phone→desktop works;
   it needs an **unwrap shim**: accept as a segment iff f1 is 32 bytes, f4 (data count) = 1, f3 = 0, not
   parity, and keccak256(f7) == f1; payload = f7. loam-transport (phones) needs the same shim.
   Fields: f1 hash, f2 length, f3 index, f4 data count, f5 parity count, f6 isParity, f7 payload.
   Nesting: `WakuMessage.payload = SDS{f5 = SegmentMessage{f7 = app}}`.

   | Direction | Channel API | loam_core raw peel |
   |---|---|---|
   | phone 0.38.1 → desktop 0.39 | dropped | works |
   | desktop 0.39 → phone 0.38.1 | wrapped bytes reach app | needs shim |
   | 0.39 ↔ 0.39 | works | needs shim |

2. **RLN on `logos.test`** (module preset table `rln_presets.cpp:50-64`: on, validation OFF, 600 s epoch).
   - No RLN modules installed → bring-up `Failed`, non-fatal (`.cpp:1252-1263`).
   - No membership: `start` non-fatal in code (`node_factory.nim:461-477`, 80 s budget) — docs say it fails;
     UNVERIFIED. Receive works (no validator when validation off, `relay.nim:202-206`). **Every send fails**
     (`publish.nim:63-74`).
   - RLN-off without code changes: (a) env `LOGOS_DELIVERY_RLN_PRESETS` → file `{"logos.test":{"enabled":false}}`
     in the host process env (`rln_presets.cpp:125-186`); (b) `preset:""` + `clusterId:2`,
     `numShardsInNetwork:8`, fleet entry nodes (loam_core must stop forcing `logos.test`,
     `loam_core_impl.cpp:108`). Both only work while the fleet doesn't validate proofs. `logos.dev` = cluster 3.
   - Membership: install `liblogos_rln_module` 0.10.0 + `liblogos_lez_rln_module` 4.2.1 (catalog
     `logos-rln-modules/releases/download/index/logos-repo.json`); `wallet_status` → payer account; fund
     ≥ 2e8 native LEZ testnet (1e6 for rate 100 + ~1.8e8 fee reserve, mostly refunded); active in 1–3 min.
     Faucet UNVERIFIED (`claim_tokens` exists in lez module). `LEZ_RLN_PAYER_KEY`: one funded key can pay
     for many nodes' memberships. A membership can't be shared (copying the keystore leaks the secret).
   - Limit 100 msgs / 600 s per membership; each segment counts. Proofs now generated by the sending
     client (no RLN-as-a-service via lightpush) → an Edge phone sending needs its own membership.
   - With membership and quota 0, sends park and fail after `maxParkedAgeSec` (1800).

3. **Two library patches lost on desktop** (present in our Linux 0.1.4 lgx): SDS persistence memory-only
   (`channel_lifecycle.nim`, SIGSEGV avoidance) and deliver-despite-missing-causal-deps
   (`scalable_data_sync.nim`). v0.39 has SDS persistence ON and still holds messages for missing deps.
   loam_core mostly unaffected (raw event); whisperbox_core (channel event) affected.

4. **API changes to absorb** (`src/delivery_module_plugin.h`, fork vs v0.3.0):
   - `messageReceived(hash, topic, payload, ts)` → `(hash, topic, payload, source, ts)`; source = live|history.
   - Unchanged: createNode, start/stop (completion via `nodeStarted`), send, subscribe/unsubscribe,
     channelCreate(channelId, contentTopic, senderId), channelSend, channelExists, channelClose, getNodeInfo.
   - Removed: `version()` (`a81e255`). New: storeQuery, getConnectionStatus, rlnState/rlnRespond/
     rlnBridgeEnable, events `messageQueued`, `rlnStateChanged`, 4× `dispatchRln*RequestEvent`.
     Metrics now prefixed `logos_delivery_`.
   - loam_core: raw handler `a.at(3)` as timestamp (`loam_core_impl.cpp:82`, `size()<4` at :77) → now the
     source string; read ts from the last element. Marks node ready on start dispatch → wait for
     `nodeStarted(success)`. Call sites `loam_core_impl.cpp:49-67, 244`, raw subscription :74-87.
   - whisperbox_core: typed `onMessageReceived` :336, `onChannelMessageReceived` :344 → rebuild against
     new header; createNode/start :375-377; subscribe + channelCreate :396-397; send/channelSend :421/:445/:493.
   - Raw `messageReceived` still fires for channel traffic (`reliable_channel.nim:416-425`, `recv_service.nim:142`).
   - Store backfill ON by default, replays with `source:"history"` → dedup by message hash.

5. **Config.** Layered `{mode, preset, messagingOverrides, channelsOverrides}`; `messagingOverrides` takes
   `MessagingClientConf` keys (`messaging_conf.nim:14-122`): tcp-port, discv5-udp-port (default 0),
   entryNodes, discv5Discovery, quicSupport, nat, logLevel, nodekey, store, backfill, rate-limit,
   rlnDisableValidation… `mode` sets relay/filter/lightpush/PX (`applyMode` :124-143); relay/staticnodes
   only via `kernelConf` (`entryLayer:"kernel"`) or flat. Ours →
   `{"mode":"Core","preset":"logos.test","messagingOverrides":{"entryNodes":[…],"logLevel":"INFO"}}`.
   Flat caveats: unknown keys are errors; `tcpPort` defaults 60000 (0 layered); QUIC default on
   (`6a4c3fda`, `cli_args.nim:742`); preset names exact (`rln_presets.cpp:15-26`). qaku, perun, whisperbox
   pass `relay`/`entryNodes`/`logLevel` top-level → flat.
